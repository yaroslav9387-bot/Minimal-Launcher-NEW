# Minimal Launcher — состояние проекта

## Что уже изменено в этой рабочей копии

- Название приложения и окна — **Minimal Launcher**, bundle identifier — `net.minimal.launcher`.
- Подключена отдельная тёмная оболочка с зелёными акцентами: навигация, главная страница, быстрые действия, библиотека, моды, серверы, друзья и настройки.
- Главная страница использует реальные локальные профили и существующий механизм запуска Minecraft; создание и импорт сборок открывают штатные окна лаунчера.
- Экран модов в новой оболочке выбирает Modrinth и использует прямой API Modrinth. Установка передаётся существующему потоку установки контента.
- Экран серверов хранит адреса локально и подключается через штатный механизм Quick Join.
- Экран друзей пока является локальным списком игровых ников. Онлайн-статусы, чат, звонки, группы и приглашения не представлены как работающие онлайн-функции.
- Сторонние Millida API-вызовы из frontend API-слоя заблокированы локальной ошибкой; аккаунт Millida не считается действительным.
- Rust-клиент прокси/зеркала больше не направляет запросы через Millida: загрузки игровых ресурсов идут напрямую к исходным поставщикам.
- Телеметрия выключена. Updater не имеет настроенных endpoint-адресов, а fallback-источники обновлений пусты.
- Удалён чужой Microsoft Entra client ID. Вход Microsoft будет доступен только после настройки собственного `MINIMAL_LAUNCHER_MS_CLIENT_ID`; офлайн-профиль остаётся доступен.
- Лицензия GPL-3.0-only и необходимые исходные уведомления сохранены.

## Что пока не готово / ограничения

- Это **не готовый релиз**. В среде разработки нет Bun, Rust toolchain и Windows SDK, поэтому TypeScript build, Rust tests и Windows Tauri build здесь не выполнены.
- Вход Microsoft не заработает до регистрации собственного приложения Microsoft Entra и сборки с `MINIMAL_LAUNCHER_MS_CLIENT_ID`.
- Онлайн-друзья, чаты, голос, приглашения, облачная синхронизация и хостинг требуют собственного backend/relay-сервиса; его ещё нет.
- Автообновление выключено до появления собственного подписанного канала обновлений и ключа подписи.
- В исходном форке остаются legacy-модули и названия Millida для миграции/совместимости. Их нельзя удалять массовой заменой: часть команд ещё используется в старых экранах или тестах. В новой оболочке эти старые разделы не открываются.
- Поддержка CurseForge в новой оболочке не включена; каталог использует Modrinth.

## Что нужно проверить на Windows перед выпуском

1. `bun install --frozen-lockfile`
2. `bun run typecheck`
3. `bun run test`
4. `bun run build:web`
5. `cd src-tauri; cargo test; cd ..`
6. `bun run build:release`
7. Установить полученный пакет на чистой Windows и проверить создание сборки, Java, запуск Vanilla/Fabric, импорт, Modrinth и Quick Join.

Не распространять эту рабочую копию как проверенный `.exe` до прохождения этих шагов.
